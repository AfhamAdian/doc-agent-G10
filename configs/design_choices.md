# Per-stage design choices (A2 deliverable)

Only stages implemented so far are documented. Empty rows are intentionally left for later work; they do
not claim that retrieval, the agent, RL/RLVR, serving, or evaluation has been completed.

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Build an auditable knowledge base from Bangla-English Grade 10 science textbooks so later answers can retain page-level evidence. | Three declared NCTB source documents: Physics, Chemistry, and Biology. The corpus provenance file declares about 450 pages and 60,000+ words; these full-corpus totals still require a successful production build for runtime confirmation. Held-out pages are kept under `grading_kit/heldout_pages/`. | No learned model at this stage. | Document-level source separation, explicit provenance, held-out exclusion, stable page identity, and production quality gates. | `configs/config.yaml` is the single parameter source. `device` supports `auto`, `cpu`, and `cuda`. A reversible pilot selects books/page limits and writes to a separate index path. | YAML configuration, Pydantic contracts, Bash build/download entry points, and pytest contract tests. | The build can run on CPU or CUDA. Current local pilot configuration forces CPU; a prior persisted pilot artifact records a CUDA build. | Deterministic IDs, configuration hashing, build metadata, page/word/region/chunk counts, and held-out contamination checks make the build auditable. |
| 1 Ingest+Enhance | Convert the source PDFs into stable page images without degrading already-clean vector-rendered textbook pages. | `physics.pdf`, `chemistry.pdf`, and `biology.pdf` in `data/raw/`; rendered RGB PNG pages in `data/interim/pages/<book>/`. Pilot mode can require only selected books and cap source pages. | No learned enhancement model is used: `enhance.enabled: false`, model/type `none`. | Validate PDF presence/readability, render with PyMuPDF at 300 DPI RGB, exclude held-out filenames, validate images with OpenCV, and use configurable classical denoise/binarization only when requested. | Stable names such as `physics-001.png`; cached renders are reused. The committed preprocessing path is pass-through because the PDFs are clean and vector-rendered. Full mode requires at least 300 usable pages and more than one source document; pilot mode keeps shared integrity checks without production-size gates. | PyMuPDF, OpenCV, existing `loader.py`, `preprocess.py`, and `enhance.py`; `get_data.sh` supports either all books or selected positional book names. | Rendering is device-independent and CPU-compatible. Runtime page artifacts remain under `data/interim/`; no new coding files are generated. | Render caching supports restartability. Tests verify real PDF rendering, stable names, cache reuse, held-out exclusion, 20-page pilot selection, and the expected 19 usable pages when `physics-017.png` is held out. |
| 2 Layout | Detect and classify page regions so OCR reads text-bearing content in deterministic reading order and ignores genuine figures. | Rendered textbook page PNGs represented by stable `Page` contracts. | Pretrained YOLO11 document-layout checkpoint `yolo11n_doc_layout.pt` from `Armaggheddon/yolo11-document-layout`. | Object detection at confidence 0.5; DocLayNet-style labels are mapped into the fixed `text`, `table`, `figure`, and `heading` contracts. | Formula regions map to `text`; tables, headings, and text remain OCR-readable; only figures/pictures are skipped later by OCR. Regions are sorted by page, vertical position, then horizontal position. | Ultralytics YOLO with Hugging Face Hub checkpoint download; model loading occurs when layout detection runs. | The shared device resolver passes CUDA device `0` when available/selected and `cpu` otherwise. | Repository ID, checkpoint filename, confidence threshold, and device are configuration-controlled. Region counts are written into build metadata. A real local YOLO inference run was not completed during the cancelled 20-page attempt. |
| 3 OCR | Transcribe Bangla plus English/Latin text and numbers from detected page regions while retaining exact page provenance. | Cropped text, table, formula-as-text, and heading regions; figures are excluded. | Pretrained EasyOCR with `bn` and `en` language packs; paragraph mode enabled. | Crop validation, RGB conversion, multilingual recognition, per-page processing, deterministic OCR chunk creation, and OCR-time PII redaction for emails and Bangladesh phone numbers. | EasyOCR receives `gpu=True` only when the shared device resolves to CUDA. Cache fingerprints include the page image bytes, layout/OCR configuration, region boxes, and kinds, so changed inputs invalidate stale OCR. | EasyOCR, OpenCV, Pillow, JSON caches, and Pydantic `Chunk` contracts. Alternative reader code paths exist, but the configured and documented choice is EasyOCR. | CPU and CUDA are supported. OCR cache files are persisted under `data/interim/ocr/`, allowing interrupted work to resume page by page. | Tests verify cache reuse and deterministic IDs with a controlled recognizer, but do not measure real EasyOCR accuracy. Build metadata records OCR-region and pre-overlap word counts. The existing 50-page-request pilot artifact records 254 OCR regions and 9,415 words. |
| 4 Index | Turn OCR output into reproducible, multilingual searchable passages and persist an exact vector knowledge base with citations. | OCR `Chunk` objects containing Bangla-English text, `doc_id`, and source `page_ids`. | Pretrained `intfloat/multilingual-e5-large` embeddings (1024 dimensions) and non-learned FAISS `IndexFlatIP`. | Sentence-boundary chunking using Bangla danda/double danda, OCR pipe fallback, newlines, and Latin punctuation; word-boundary fallback for long unpunctuated OCR; `passage:` E5 prefixes; L2-normalized embeddings; exact inner-product search. | Chunk size 500 characters and overlap target 50 characters. Chunk IDs are deterministic. CPU batch size is 4 and GPU batch size is 16. Vector/chunk counts and normalization are checked; held-out page references are rejected again before persistence. | `sentence-transformers`, NumPy, and `faiss-cpu`; `build_index.sh` performs one build and then reloads/validates the persisted artifact. | Production artifacts go to `data/index/`; pilot artifacts go to `data/index-pilot/`, and code rejects identical paths. Files are `index.faiss`, `chunks.jsonl`, and `metadata.json`. | Metadata records corpus counts, pilot status, model, dimension, device, index type/bytes, and configuration SHA-256. Tests exercise real FAISS build/reload/search with controlled normalized embeddings. The existing 50-page-request CUDA pilot artifact contains 47 usable pages, 295 chunks, 1024-dimensional vectors, and a 1,208,365-byte index. |
