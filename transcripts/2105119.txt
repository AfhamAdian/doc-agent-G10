Agent :
Yes—you can build the FAISS index on Kaggle’s GPU and download the finished index to test locally. That’s a sensible workflow.
On Kaggle:
Upload/clone the repository and provide the PDFs under data/raw/.
Enable a GPU accelerator.
Set:
device: cuda

pilot:
  enabled: false
Install and build:
pip install -e .
python scripts/run_index.py
Download the complete index directory:
tar -czf /kaggle/working/doc-agent-index.tar.gz -C data index
Locally, extract it from the repository root:
tar -xzf ~/Downloads/doc-agent-index.tar.gz -C data
You should then have:
data/index/
├── index.faiss
├── chunks.jsonl
└── metadata.json
Keep all three files together. Also ensure the local configuration uses exactly the same embedding model and dimension:
embed:
  model: "intfloat/multilingual-e5-large"
  dim: 1024

index:
  type: "flat"
  path: "data/index"
Important caveats:
Local query processing still loads multilingual-e5-large, because every user question must be embedded using the same model. Kaggle eliminates the expensive document indexing work, but not query embedding.
Use compatible faiss-cpu versions on Kaggle and locally; this project expects >=1.8,<1.9.
If you leave pilot.enabled: true, Kaggle writes to data/index-pilot, not data/index. You would need to copy that directory and change index.path locally.
The current repository cannot yet test the whole application end-to-end: retrieval, reranking, agent logic, tools, and the /answer endpoint still contain NotImplementedError. The downloaded index can be loaded and tested, but those later stages must be implemented before the complete app works.

what can be the weaknesses, tell me some

Agent:
Possible A3 weaknesses for your project include:
Evidence-score calibration: the agent may treat a relevant low-scoring chunk as weak evidence or accept an unrelated high-scoring chunk.

Re-search effectiveness: with exact FAISS retrieval, widening k does not change the original top-1 result. Recovery depends on reranking lower-ranked candidates effectively.

Bangla reranking quality: an English-trained reranker may perform poorly on Bangla, Banglish, and Bangla–English code-mixed questions.

OCR errors: incorrect conjuncts, matras, subscripts, superscripts, formulas, and scientific symbols may prevent retrieval of the correct passage.

Formula normalization: equivalent forms such as H₂SO₄, H2SO4, and OCR-corrupted versions may be treated as different expressions.

Romanized Bangla queries: questions such as “salok songshleshon ki?” may not match Bangla textbook text consistently.

Tables and diagrams: facts contained in tables, captions, or diagram labels may be retrieved in the wrong order or without enough context.

Multi-chunk questions: comparison and explanation questions may require evidence from two or more chunks, while the agent may answer using only one.

Chunk-boundary problems: a definition, equation, or explanation may be split between adjacent chunks despite semantic chunking.

Wrong-page citations: the answer may be correct but cite a nearby or topically similar page rather than the page that directly supports it.

Unsupported synthesis: the LLM may combine textbook evidence with its pretrained knowledge and add claims not found in the cited chunks.

Over-abstention: a conservative grounding threshold may protect groundedness but refuse too many answerable questions.

Under-abstention: a permissive threshold may improve answer coverage but allow hallucinated or weakly supported answers.

Out-of-corpus confusion: the agent may answer Class 11–12, medical, or current-affairs questions from pretrained knowledge instead of abstaining.

Prompt injection: OCR text or a user query may contain instructions such as “ignore previous rules,” which the agent must not follow.

Human escalation ambiguity: the system may escalate too frequently or fail to escalate when OCR evidence is genuinely unreadable or conflicting.

Latency and memory: multilingual-e5-large, reranking, repeated retrieval, and full-page reading may be slow or memory-intensive on CPU/Colab.

Threshold transfer: a threshold calibrated on Physics may not work equally well for Chemistry formulas and Biology terminology.

Evaluation-set leakage: questions written from indexed pages rather than genuinely held-out pages could exaggerate performance.

Gold-answer ambiguity: some science explanations have several valid wordings, making exact-match evaluation unreliable.

Small evaluation set: too few questions may not represent all three subjects, scripts, question types, and failure modes.
